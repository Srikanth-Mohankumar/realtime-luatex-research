# TeX Engine Fundamentals: Paragraphs Are Local, Pages Are Global

**Purpose.** The texlode preprint (Lode, "Real-Time LuaTeX: Recompiling Large Documents in
1ms", `sources/lode-realtime.pdf`) rests on one structural property of the TeX engine:

> Line breaking is paragraph-local; page breaking is global but not perceptually immediate
> and therefore need not block the editing loop.

This note documents that property from the engine's side: how the paragraph builder works,
exactly which inputs determine its output, where LuaTeX's Lua hooks sit in the pipeline,
why the page builder is inherently stateful, and how boxes, glue, kerns, and insertions
participate. The closing section tabulates which layout computations are O(paragraph) and
which are O(document).

**Sources.** Victor Eijkhout, *TeX by Topic* (free 2007 PDF edition; chapter numbers below
refer to that edition — notably ch. 5 Boxes, 8 Dimensions and Glue, 15 Baseline Distances,
16–19 Paragraph Start/End/Shape/Line Breaking, 26–27 Page Shape/Page Breaking, 29
Insertions); the *LuaTeX Reference Manual* (TeX Live 2025; §5 Languages/characters/fonts,
§9.5 node-list callbacks, §10.3.17.3 `tex.linebreak`); D. E. Knuth and M. F. Plass,
"Breaking Paragraphs into Lines", *Software—Practice and Experience* 11 (1981) 1119–1184;
`tex.web` for the page-cost constants. Callback ordering in §2 was verified empirically
against the local `luatex` 1.23.x binary (TeX Live 2025).

## 1. The paragraph builder

### 1.1 From tokens to a horizontal list

TeX is always in a *mode*. In (external) vertical mode, any *horizontal command* — a
character, `\char`, an inline `$`, `\hskip`, `\indent`, `\noindent`, `\unhbox`, etc. —
starts a paragraph (TbT ch. 16):

1. `\parskip` glue is appended to the enclosing vertical list (unless that list is an
   empty internal one, e.g. the start of a `\vbox`).
2. TeX switches to unrestricted horizontal mode with an empty horizontal list; for
   `\indent` an empty `\hbox` of width `\parindent` is placed first (this *indentation
   box* is a real node — it can be removed with `{\setbox0=\lastbox}`).
3. The `\everypar` token list is inserted into the input.
4. The page builder is exercised (to move the `\parskip` glue to the current page —
   note this happens while in horizontal mode).

From then on, everything the execution processor produces — characters, glue from spaces
(sized by the current font's `\fontdimen`s and modulated by `\spacefactor`/`\sfcode`),
explicit kerns and skips, boxes, discretionaries, whatsits, math — is appended to one flat
**horizontal list**. Nothing is broken yet; the list simply grows.

The paragraph ends at the primitive `\par` command (typed, generated by an empty line, or
inserted because a *vertical command* such as `\vskip` occurred in horizontal mode; also
when a `}` closes a `\vbox`/`\insert`/`\output` group in horizontal mode). `\par` appends
the equivalent of (TbT §17.1.2):

```tex
\unskip \penalty10000 \hskip\parfillskip   % plain/LaTeX: 0pt plus 1fil
```

then hands the finished horizontal list to the **line breaker**, appends the resulting
lines (plus interline glue and penalties) to the enclosing vertical list, clears the
paragraph-shape parameters (`\parshape`, `\hangindent`, `\hangafter`, `\looseness`), goes
back to vertical mode, and exercises the page builder.

Crucially, the parameters that govern breaking are read **when the paragraph is finished**,
not while it is collected (TbT §17.2.1): `... last words.}\par` uses the values *outside*
the group. What is frozen *during* collection is the content itself: font choices, glue
sizes computed from `\spacefactor`, explicit discretionaries, math already converted to
horizontal material.

### 1.2 The box/glue/penalty model and legal breakpoints

Knuth–Plass abstracts a paragraph into three node species:

- **boxes** — indivisible material of fixed width (characters, ligatures, `\hbox`es,
  rules);
- **glue** — white space with a natural size plus *stretch* and *shrink* components
  (§5 below);
- **penalties** — numeric "aesthetic cost" markers for breaking at that spot;
  `\penalty10000` (or more) forbids a break, `\penalty-10000` (or less) forces one.

A line break may legally occur only (TbT §19.1.2):

1. at a **penalty** (cost = the penalty value);
2. at **glue** preceded by a non-discardable item (so runs of glue yield one breakpoint);
3. at a **kern** immediately followed by glue;
4. at a **math-off** followed by glue;
5. at a **discretionary** (`\discretionary{pre}{post}{nobreak}`, cost `\hyphenpenalty`
   or, for empty pre-break text, `\exhyphenpenalty`).

After a chosen break, all *discardable* items (glue, kerns, penalties, math nodes) that
follow it are dropped — this is why interword space vanishes at the end of a line.

### 1.3 Badness

Given a line stretched or shrunk to reach `\hsize`, its **badness** is (TbT §8.3.3):

```
b = min( 10000, 100 * (used stretch-or-shrink / available stretch-or-shrink)^3 )
```

Shrink is hard-bounded (shrinking past the available amount is an overfull box, b = ∞);
stretch may be exceeded, at rapidly growing badness. Badness 100 means "all stretch used";
badness 800 means spaces stretched to double their natural width (with CM's
`3.33pt plus 1.67pt` interword glue). The identical formula is used for page breaking.

Each line gets a **fitness class**: tight (3, shrunk with b ≥ 13), decent (2, b ≤ 12),
loose (1, stretched with b ≥ 13), very loose (0, stretched with b ≥ 100). Adjacent lines
whose classes differ by more than 1 are *visually incompatible*.

### 1.4 Demerits

Line breaking does not minimize badness per line; it minimizes total **demerits** over the
whole paragraph. For one line with `l = \linepenalty`, badness `b`, break penalty `p`
(TbT §19.1.3):

```
d = (l + b)^2 + p^2    if 0 <= p < 10000
d = (l + b)^2 - p^2    if -10000 < p < 0
d = (l + b)^2          if p <= -10000
```

To the sum over lines are added:

- `\adjdemerits` (plain: 10 000) for each visually incompatible adjacent pair,
- `\doublehyphendemerits` (10 000) for consecutive hyphenated lines,
- `\finalhyphendemerits` (5 000) if the penultimate line ends in a hyphen.

Because the last line is set at natural width (the infinite stretch of `\parfillskip`
absorbs the slack), it is always "decent"; TeX also pretends a decent line precedes the
paragraph.

### 1.5 The Knuth–Plass total-fit algorithm

The 1981 paper's key move is **global optimization over the paragraph** by dynamic
programming, instead of the greedy first-fit/best-fit of earlier systems:

- Scan the horizontal list left to right. At each legal breakpoint, maintain a set of
  **active nodes** — feasible previous breakpoints that could still begin the current
  line (those whose accumulated width allows a line with badness ≤ tolerance).
- For each (active node → candidate breakpoint) pair, compute the line's badness and
  demerits; keep, per (line number when needed, fitness class), the predecessor with
  minimal total demerits. Deactivate nodes that can no longer reach any future
  breakpoint within tolerance (the line would have to shrink beyond its limit).
- At the final breakpoint (the forced break at `\parfillskip`'s `\penalty10000` +
  paragraph end), follow the back-pointers of the minimal-demerits solution.

The active set is bounded by the number of feasible breakpoints per line (in practice a
handful), so the running time is effectively **linear in the length of the paragraph**,
with a small constant — the reason a 2026 laptop breaks a paragraph in tens of
microseconds. TeX can therefore afford to trade a slightly worse early line for a much
better paragraph — something a line-by-line algorithm cannot do — while remaining
paragraph-bounded. Distinct line numbers only enter the state when something is
line-number-dependent (`\parshape`, `\hangindent`/`\hangafter`, `\looseness`).

`\looseness=n` asks the optimizer to prefer, among solutions within tolerance, one with
`n` more (or, if negative, fewer) lines than the optimum; `\prevgraf` afterwards reports
the number of lines produced.

### 1.6 The three passes

TeX attempts a paragraph up to three times (TbT §19.2.1):

1. **First pass** — no discretionaries are inserted (no hyphenation); succeeds if a
   solution exists with every line's badness ≤ `\pretolerance` (plain/LaTeX: 100).
   If `\pretolerance < 0` this pass is skipped.
2. **Second pass** — the hyphenation algorithm inserts discretionaries; threshold is
   `\tolerance` (plain: 200, LaTeX: 200 by default).
3. **Emergency pass** (TeX3) — only if `\emergencystretch > 0pt`: badness is computed as
   if each line had `\emergencystretch` of extra stretchability, making near-miss
   solutions feasible. No actual glue is added, so underfull warnings can still appear.

If all passes fail, TeX produces overfull boxes rather than exceed the shrink limit.

### 1.7 Shape parameters

- **`\hsize`** — the target measure. Every line is built to width `\hsize`;
  `\leftskip`/`\rightskip` glue is added at each line's ends *inside* that measure and
  participates in the badness computation (this is how `\raggedright` works:
  `\rightskip=0pt plus …`).
- **`\hangindent` / `\hangafter`** — hanging indentation. `\hangindent>0` indents from
  the left margin, `<0` from the right; `\hangafter=n≥0` means "lines after the first
  `n` hang", `n<0` means "the first `|n|` lines hang". Implemented by *reducing
  `\hsize`* for the affected lines and then shifting the finished hboxes in the vertical
  list (TbT §18.2.1) — which is why `\leftskip` shifting and hanging indentation differ
  observably (displays, leaders).
- **`\parshape = n  i1 l1 ... in ln`** — per-line (indent, length) pairs for the first
  `n` lines; the last pair repeats for longer paragraphs. Overrides `\hangindent`.
- All of `\parshape`, `\hangindent`, `\hangafter`, `\looseness` are **cleared by
  `\par`** — they are one-shot, set by the code *preceding* the paragraph.

### 1.8 Hyphenation

During the second pass (TeX82) — in LuaTeX, unconditionally as a separate stage, see §2 —
words are located and discretionaries inserted:

- **Word detection** (TbT §19.4): starting after glue, TeX looks for a starting letter
  (nonzero `\lccode`, in LuaTeX `\hjcode`), skipping punctuation and implicit kerns; a
  trial word is the maximal run of such letters/ligatures from one font. A following box,
  rule, math formula, or explicit discretionary inhibits hyphenation of that word; an
  uppercase start inhibits it unless `\uchyph > 0`.
- **Patterns and exceptions**: `\patterns` (Liang's pattern trie; iniTeX-only in TeX82,
  loadable at any time in LuaTeX) and `\hyphenation{...}` exceptions are stored **per
  `\language`**. The "current language" is recorded *in the list itself*: TeX82 inserts a
  language whatsit whenever `\language` differs from the current language (one is placed
  right after `\everypar` at paragraph start); LuaTeX stores language,
  `\lefthyphenmin`, `\righthyphenmin` and `\uchyph` in every glyph node.
- **Feasible fragments**: at least `\lefthyphenmin` characters before and
  `\righthyphenmin` after any break (plain: 2 and 3; sum ≥ 63 disables hyphenation).
- **Discretionaries**: TeX behaves as if it inserted
  `\discretionary{\char\hyphenchar\font}{}{}` at each pattern-permitted position (no
  insertion if the font's `\hyphenchar` is out of range 0–255 or absent; `\hyphenchar`
  is initialized from `\defaulthyphenchar` at font load). `\-` is the same thing typed
  by hand. After an explicit hyphen character an empty discretionary
  `\discretionary{}{}{}` is inserted (breaking there costs `\exhyphenpenalty`); a word
  already containing a discretionary is not hyphenated further. LuaTeX generalizes the
  characters via per-language `\prehyphenchar`/`\posthyphenchar` (implicit discs) and
  `\preexhyphenchar`/`\postexhyphenchar` (explicit ones), stores
  `\hyphenpenalty`/`\exhyphenpenalty` values *inside* each disc node, and hyphenates the
  first word of a paragraph too (TeX82 does not).

### 1.9 The locality property

Everything above adds up to the load-bearing fact:

> **Breaking a paragraph into lines is a pure function of (a) the finished horizontal
> list and (b) a small, enumerable set of parameters read at `\par` time. No content of
> any other paragraph, page, or document position enters the computation.**

The inputs, exhaustively:

| Input | Where it lives |
|---|---|
| the node list: characters/glyphs + fonts, interword glue (already sized by `\spacefactor`), explicit kerns/penalties/discs/boxes/whatsits, math already converted | the horizontal list itself |
| measure: `\hsize`, `\parshape`, `\hangindent`, `\hangafter` | parameters at `\par` |
| margins/fill: `\leftskip`, `\rightskip`, `\parfillskip` (+ the `\parindent` box, already in the list) | parameters at `\par` |
| tolerances: `\pretolerance`, `\tolerance`, `\emergencystretch`, `\looseness` | parameters at `\par` |
| costs: `\linepenalty`, `\hyphenpenalty`, `\exhyphenpenalty`, `\adjdemerits`, `\doublehyphendemerits`, `\finalhyphendemerits` | parameters at `\par` |
| hyphenation: language(s) + `\lefthyphenmin`/`\righthyphenmin`/`\uchyph` | whatsits in the list (TeX82) / glyph-node fields (LuaTeX) |
| microtype: `\protrudechars`, `\adjustspacing`, per-font `\lpcode`/`\rpcode`/`\efcode` | parameters + font at `\par` (§6.4) |

The output is likewise self-contained: a sequence of hboxes (one per line, each set to its
measure with a frozen glue-set ratio), interspersed with interline penalties
(`\interlinepenalty`, `\clubpenalty`, `\widowpenalty`, `\brokenpenalty` — these affect
*page* breaking later, never the line breaks themselves) and interline glue.

The sharpest evidence that this dependency set is complete is LuaTeX's own API: the
engine's line breaker is exposed to Lua as a *stateless call* whose parameter table is
exactly the list above (LuaTeX manual §10.3.17.3):

```lua
local nodelist, info = tex.linebreak(listhead, {
  hsize = ..., parshape = ..., hangindent = ..., hangafter = ...,
  pretolerance = ..., tolerance = ..., emergencystretch = ..., looseness = ...,
  linepenalty = ..., hyphenpenalty = ..., exhyphenpenalty = ...,
  adjdemerits = ..., doublehyphendemerits = ..., finalhyphendemerits = ...,
  leftskip = ..., rightskip = ...,           -- glue_spec nodes
  interlinepenalty = ..., clubpenalty = ..., widowpenalty = ..., brokenpenalty = ...,
  pdfadjustspacing = ..., pdfprotrudechars = ...,   -- microtype hz/protrusion
})
-- info: prevdepth, prevgraf, looseness, demerits
```

Hand it any well-formed horizontal list (indent box + content + `\penalty10000` +
`\parfillskip` glue) and the same parameters, and you get the same lines — anywhere, any
time, in any document. This is precisely what makes the texlode architecture possible:
re-typesetting one edited paragraph requires only its own source (to rebuild the node
list) and a parameter snapshot, i.e. **O(paragraph) work independent of document size**.

### 1.10 Exceptions and caveats to locality

Locality holds at the *node-list + parameters* level. The boundary cases:

1. **The parameters themselves are set by surrounding code.** `\parshape`,
   `\hangindent`/`\hangafter`, `\looseness` are one-shot values planted by whatever macro
   ran before the paragraph (`\item`, `\hangfrom`, section heads); `\everypar` can inject
   arbitrary material. An incremental system must therefore snapshot the parameter state
   *at each paragraph's start*, and treat any edit that changes that state (e.g. entering
   a list environment) as invalidating the paragraph. Equally, the mapping *source text →
   horizontal list* is macro-expansion and thus stateful (fonts, counters, catcodes);
   locality is a property of the layout stage, not of TeX's macro language.

2. **Whatsits carry state through the paragraph.** Whatsits have zero size and are
   transparent to the line breaker, but they are the engine's escape hatch for stateful
   side effects: `\write` (whose output order is a document-global property), `\special`
   / PDF literals, and the language whatsits of §1.8 (the language in effect at the
   paragraph's start is itself surrounding-code state). Similarly `\mark`, `\insert`, and
   `\vadjust` items inside a paragraph *migrate* out to the enclosing vertical list
   attached to the line in which they occur — the lines carry global-coupling payloads
   even though they do not influence the breaks.

3. **Partial paragraphs: display math splits a paragraph.** `$$...$$` interrupts the
   paragraph; the text before the display is broken into lines immediately, `\prevgraf`
   keeps counting (a display counts as three lines), and the resumed text continues as
   the *same* paragraph. Consequences: with `\parshape`/`\hangindent` in effect, the
   width of the resumed part's **first line** depends on how many lines the earlier part
   produced (`\prevgraf` indexes into the shape); and the display's own layout reads
   `\predisplaysize` (effective width of the line just above), `\displaywidth`,
   `\displayindent` from the partial-paragraph context. So "first line width" is only
   locally determined for paragraphs that are not resumed fragments.

4. **Vertical placement is not part of the claim.** Where the lines land on the page —
   interline glue via `\prevdepth` (§5.4), `\parskip`, page breaking — depends on
   preceding material. Locality covers the *horizontal* decomposition into lines and each
   line's internal glue setting, which is exactly the part that is expensive and
   pixel-visible while typing.

## 2. Line breaking ↔ hooks in LuaTeX

### 2.1 From TeX82's monolith to LuaTeX's stages

In TeX82 the "paragraph pipeline" is interleaved and inaccessible: characters become char
nodes with ligatures and implicit kerns *already applied* at list-building time (needed so
`\hbox` widths are measurable); when the second pass needs hyphenation, TeX temporarily
*deconstructs* each word (undo ligatures, ignore kerns), runs the pattern matcher, and
splices reconstructed, re-ligatured fragments back (LuaTeX manual §5.1).

LuaTeX decomposes this into independent, individually replaceable stages. Characters stay
raw "character" glyph nodes (no font processing) while the list is collected — each glyph
node carrying its font, language, and hyphenmin data. When the paragraph is typeset:

1. **hyphenate** — discretionaries are inserted into the *whole* list, up front and
   unconditionally (verified below: the stage runs even when `\pretolerance` would let
   the first pass succeed; the first pass simply ignores discretionaries). Exposed as
   `lang.hyphenate(head[, tail])`.
2. **ligaturing** — ligatures are built over the list, including inside the three
   branches of discretionaries (the manual's `of-f-ice` example) and across word
   boundaries. Exposed as `node.ligaturing(head)`.
3. **kerning** — implicit font kerns are injected; remaining "character" nodes become
   final "glyph" nodes. Exposed as `node.kerning(head)`.
4. **line breaking** — Knuth–Plass over the prepared list.

Math gets the same treatment: the conversion of a math list to horizontal material is one
replaceable stage, the **`mlist_to_hlist`** callback (and `node.mlist_to_hlist()`).

### 2.2 Callback order around a paragraph (verified on TeX Live 2025)

Probe: register logging functions for all paragraph-related callbacks in plain `luatex`
and typeset one paragraph. Result (`luatex` 1.23, TeX Live 2025):

```
insert_local_par        (new_graf)      -- paragraph starts (local par node created)
buildpage_filter        (new_graf)      -- page builder exercised after \everypar
hyphenate                               -- discretionary insertion   (\par arrives)
ligaturing                              -- ligature construction
kerning                                 -- implicit font kerns
pre_linebreak_filter                    -- full list, \parfillskip already appended
  [ linebreak_filter ]                  -- replaces Knuth-Plass entirely if set
post_linebreak_filter                   -- the stack of line hboxes
  [ append_to_vlist_filter ]            -- each box added to the vertical list
buildpage_filter        (hmode_par)     -- page builder runs on the new material
```

Notes on the individual hooks (LuaTeX manual §9.5):

- **`pre_linebreak_filter(head, groupcode)`** — "called just before LuaTeX starts
  converting a list of nodes into a stack of `\hbox`es, after the addition of
  `\parfillskip`." As measured, it fires *after* the hyphenate/ligaturing/kerning
  stages. Return `true` (keep), a new head (replace), or `false` (discard).
- **`linebreak_filter(head, is_display)`** — *replaces* the internal Knuth–Plass run;
  must return a vertical-mode list containing at least one hbox. Returning a non-node
  falls through to the internal algorithm.
- **`post_linebreak_filter(head, groupcode)`** — sees the finished lines (hboxes +
  penalties + glue) before they are appended; the natural interception point for a
  system that wants each line's final node list (this is where texlode-style display-list
  extraction can read every glyph's position within its line box).
- **`hyphenate(head, tail)` / `ligaturing(head, tail)` / `kerning(head, tail)`** —
  replace the three preparation passes; setting one to `false` disables that pass.
  A custom `hyphenate` must insert disc nodes itself (`lang.hyphenate` is available to
  delegate); overriding only one of ligaturing/kerning requires performing the paired
  bookkeeping (boundary-node cleanup) the internal code would have done.
- **`hpack_filter` / `vpack_filter`** — every `\hbox`/`\vbox` packaging (with target
  size and packtype); **`hpack_quality`/`vpack_quality`** intercept over/underfull
  diagnostics.
- **`mlist_to_hlist(head, display_type, need_penalties)`** — replaces math-to-horizontal
  conversion.
- **`insert_local_par`** — fires at paragraph start when the `local_par` node (paragraph
  direction, local boxes) is created.
- **`contribute_filter` / `buildpage_filter` / `build_page_insert` /
  `pre_output_filter`** — the page-builder-side hooks: material moving to the
  contribution list / to the current page (with a reason string: `new_graf`,
  `hmode_par`, `vmode_par`, `insert`, `penalty`, `after_output`, ...), insert handling,
  and the packaging of `\box255` for `\output`.

The decomposition matters for the locality argument in two ways. First, it proves the
stages are *separable*: each of hyphenate/ligaturing/kerning/linebreak is a list-in,
list-out transformation with no hidden coupling (a Lua function can replace any of them).
Second, it gives an incremental system its interception points: grab the paragraph after
`post_linebreak_filter` and you hold the complete, final, positioned typographic content
of that paragraph — before any page-level decision has been made.

## 3. The page builder

### 3.1 Current page and recent contributions

TeX's main vertical list is split in two (TbT §27.1):

```
main vertical list = [ current page ] ++ [ recent contributions ]
```

New vertical material (paragraph lines, skips, penalties, inserts) is appended to the
**recent contributions**. "Exercising the page builder" means moving contributions onto
the **current page**, one item at a time, updating running totals and evaluating the cost
of breaking *at each legal breakpoint as it arrives*. The page builder runs (TbT §27.2):

- around paragraphs (after `\everypar` insertion, and after the broken paragraph is
  added to the vertical list);
- around display formulas;
- after `\par`, boxes, insertions, and explicit penalties in vertical mode;
- after an output routine ends.

While the current page is empty, discardable items moving to it are dropped (glue vanishes
at page tops); when the first box arrives, `\topskip` glue is inserted above it (§3.5).

### 3.2 `\vsize` vs `\pagegoal`, and the accumulators

When the first box, rule, or insertion reaches the current page, the *then-current*
`\vsize` is copied into **`\pagegoal`** — a snapshot, not looked at again until after
`\output` (changing `\vsize` mid-page has no effect on this page; changing `\pagegoal`
does). Insertions later *reduce* `\pagegoal` (never `\vsize`) by their effective sizes
(§7). Alongside it the page builder maintains, as automatically-global "special dimens":

| Register | Meaning |
|---|---|
| `\pagetotal` | accumulated natural height of the current page |
| `\pagestretch` | accumulated 0th-order (finite) stretch |
| `\pagefilstretch` / `\pagefillstretch` / `\pagefilllstretch` | accumulated fil / fill / filll stretch |
| `\pageshrink` | accumulated shrink |
| `\pagedepth` | depth of the current page (zeroed after trailing kern/glue) |
| `\insertpenalties` | accumulated penalties from split insertions |

An empty page has `\pagegoal = \maxdimen`, `\pagetotal = 0`.

### 3.3 Cost, and when the decision falls

For each potential breakpoint moved to the current page, badness `b` is computed exactly
as for a line: stretch/shrink the page material to height `\pagegoal` with maximum depth
`\maxdepth`. With `p` the penalty at the break and `q = \insertpenalties` (tex.web values;
TbT §27.4.3):

```
c = p                if p <= -10000 and b < infinity   (forced break)
c = b + p + q        if b < 10000 and |p| < 10000
c = 100000           if b = 10000 and |p| < 10000      ("deplorable" but finite)
c = infinity         if b = infinity (overfull) or q > 10000
```

The **least-cost breakpoint so far is only remembered**. The page is actually broken —
material up to the best break goes into `\box255`, `\outputpenalty` is set, the remainder
is pushed back onto the contributions — only when `c = infinity` (the page overflowed) or
`p <= -10000` (forced). This is the engine's *lazy* page breaking: TeX keeps accepting
material past the goal until something proves the optimum has passed. TbT §27.6.3 shows
the consequence: with `\vsize` two lines high and a three-line paragraph contributed, the
output routine does *not* run at `\par` — it fires when the *next* paragraph starts. A
page's content is therefore never final until the page builder has seen material beyond
it. (`\vsplit` exposes the same breakpoint computation for arbitrary vboxes, with
`\splittopskip`/`\splitmaxdepth` in the roles of `\topskip`/`\maxdepth`.)

### 3.4 `\topskip` and `\maxdepth`

- **`\topskip`** (plain: `10pt`): before the first box of each page, glue is inserted
  with `\topskip`'s stretch/shrink and natural size `max(0, topskip - height(first
  box))`. Effect: first baselines sit at a constant offset from the page top, regardless
  of the first line's ascenders. Plain TeX's `\raggedbottom` works by giving `\topskip`
  finite stretch (`10pt plus 60pt`) — see §5.3.
- **`\maxdepth`** (plain: `4pt`): maximum depth of the page box. If adding an item would
  exceed it, the page's reference point moves down so depth is exactly `\maxdepth` —
  the excess counts against the height, keeping visually equal page bottoms.

### 3.5 Why page breaking is global and stateful

Contrast with §1.9. The cost of breaking at any point depends on `\pagetotal`,
`\pagestretch`(+fil orders), `\pageshrink`, `\pagedepth`, `\pagegoal`, and
`\insertpenalties` — every one an *accumulation over everything contributed since the
last page break*, with `\pagegoal` itself eroded by every insertion seen so far (§7), and
insertions held over from *previous* pages still queued. The decision is made online,
single-pass, with no backtracking beyond "best break so far": once `\box255` ships, the
break is irrevocable. So:

- page N's break depends on page N's entire content, which starts where page N−1 broke,
  recursively back to page 1: the state is **O(document prefix)**;
- a one-line change in one paragraph can shift its page's break, which shifts every
  subsequent break (and every held-over insertion) — the classic full-recompile cascade;
- unlike Knuth–Plass over a paragraph, there is no engine-level global optimization over
  page breaks (that would require the whole document in memory and multi-pass costs;
  cf. LaTeX packages and the literature on globally optimized pagination).

This asymmetry — *optimal-within-paragraph, greedy-across-pages* — is a deliberate TeX82
design point (memory), and it is exactly the seam the texlode preprint exploits: the
expensive, pixel-perfect, user-visible computation (lines) is local; the global one
(pages) is cheap per unit but unbounded in scope, and its latency can be hidden.

## 4. The box model

### 4.1 `\hbox`, `\vbox`, `\vtop`

A box is a rectangle with a **reference point** on its left edge and three dimensions:
**width** (rightward), **height** (above the baseline through the reference point),
**depth** (below it).

- **`\hbox`** — components sit side by side, reference points on the common baseline
  (vertical excursions only via `\raise`/`\lower`). Width = sum of component widths
  (negative kerns/glue can make it negative); height/depth = max component
  height/depth above/below the baseline (never negative at creation).
- **`\vbox`** — components stack; reference points aligned on the left vertical edge
  (horizontal excursions via `\moveleft`/`\moveright`). Reference point at the
  **baseline of the last component**: depth = depth of the last box (zero if the box
  ends with glue/kern), height = everything else. Width = max rightward extent
  (material left of the reference line is ignored). Depth is clipped to
  `\boxmaxdepth` by moving the reference point down.
- **`\vtop`** — same construction as `\vbox`, but the reference point sits at the
  **baseline of the first component**: height = height of the first box (zero if the
  first item is not a box or rule), depth = the rest.

`\hbox to <dim>` / `spread <dim>` force a size by setting the internal glue (§5.2);
`\vcenter` (math only) centers on the math axis.

### 4.2 Boxes as immutable typeset units

Once packaged, a box is *set*: every glue item inside has been assigned its final width
via the box's glue-set ratio, badness has been computed (`\badness`), and the box behaves
as an opaque rectangle. `\wd n`, `\ht n`, `\dp n` read the dimensions of box register `n`
— and can be *assigned* (`\wd0=0pt`), which lies to TeX about the box's size for all
subsequent placement arithmetic **without re-setting its contents** (the `\smash` idiom).
Such assignments are global. Registers are used destructively by `\box n` (append and
void) or non-destructively by `\copy n`.

Decomposition back into list material:

- **`\unhbox n` / `\unvbox n`** — append the box's *contents* to the current
  horizontal/vertical list (mode must match), voiding the register; `\unhcopy`/`\unvcopy`
  keep it. Crucially, unboxing *unfreezes glue*: the contents rejoin the current list as
  raw nodes whose glue can be re-set by the next packaging (this is why plain's output
  routine `\unvbox`es insertion boxes — so page glue stretches uniformly). `\unvbox`
  does not update `\prevdepth`, and unboxed text does not regain hyphenation whatsits.
- **`\lastbox`** — the last item of the current list, if a box; assigning it
  (`{\setbox0=\lastbox}`) removes it from the list (used to strip the indentation box).
  Void on the main vertical list — you cannot dissect the page in progress, only
  `\box255` inside `\output`. Shift amounts from `\raise`/`\moveleft` etc. are lost.

Positioning adjustments: `\raise`/`\lower` (boxes in horizontal lists),
`\moveleft`/`\moveright` (boxes in vertical lists) — these shift the box relative to the
current line/column without affecting its recorded dimensions (except hbox height/depth
accounting for raised content, as above).

For the research programme the relevant reading is: **a line produced by the paragraph
builder is an immutable hbox** — its internal geometry is final and context-free; all the
page builder ever does with it is measure `(height, depth)` and stack it. That is the
contract that lets line boxes be cached, shipped to a renderer as display lists, and
re-stacked under new page breaks without re-typesetting.

## 5. Glue

### 5.1 Anatomy and orders of infinity

A glue specification has a natural size plus optional stretch and shrink:

```tex
\skip0 = 10pt plus 3pt minus 2pt
```

Stretch/shrink may be *infinite* in three strictly ordered ranks: `fil`, `fill`, `filll`
— any amount of a higher order overpowers all lower-order stretch in the same list
(`plus 16384pt` loses to `plus 0.0001fil`). Shorthands:

| Horizontal | Vertical | Meaning |
|---|---|---|
| `\hfil` | `\vfil` | `0pt plus 1fil` |
| `\hfill` | `\vfill` | `0pt plus 1fill` |
| `\hss` | `\vss` | `plus 1fil minus 1fil` |
| `\hfilneg` | `\vfilneg` | `minus 1fil` (cancels one `fil`) |

Finite shrink is a hard floor (shrinking further = overfull); finite stretch is a soft
ceiling (exceeding it = high badness, §1.3). Kerns are glue's rigid sibling (§6).

### 5.2 Glue setting

When a box must differ from its natural size, only the glue of the **highest order
present** is set, every item of that order by the **same ratio** (TbT §8.3.2). The result
is recorded in the box as the *glue set*: in LuaTeX node terms, the hlist/vlist fields
`glue_set` (the ratio), `glue_order` (0–3), `glue_sign` (stretch/shrink). A line hbox from
the paragraph builder carries exactly this frozen triple — the last line's
`\parfillskip` fil normally makes it `glue_order=1, glue_set≈` (fraction of the fil
used). Setting a box `to`/`spread` a size beyond finite shrink gives an overfull box
(reported per `\hfuzz`/`\vfuzz`, `\hbadness`/`\vbadness`); beyond finite stretch,
underfull.

### 5.3 Fil-level stretch in the page goal: `\raggedbottom`

Badness collapses to 0 whenever infinite stretch is available (the ratio's denominator is
infinite at that order). Applied to pages: if `\pagefilstretch > 0` at a breakpoint, the
height mismatch to `\pagegoal` costs nothing — **every stopping point is "feasible" and
page breaks are then governed by penalties alone** (`c = 0 + p + q`). That is why a
stray `\vfil` on the page changes page-breaking behaviour completely, and why the two
classic ragged-bottom implementations read as they do:

- **Plain TeX**: `\raggedbottom` gives `\topskip` stretch — `10pt plus 60pt` — which
  enters `\pagestretch` on every page (finite, so badness is merely *small* rather than
  zero across a ~60pt window of page lengths); the output routine then sets the glue at
  natural size and pads the bottom with `\vfil` at shipout.
- **LaTeX**: `\raggedbottom` defines `\@textbottom` as `\vskip \z@ \@plus.0001fil`
  (and `\flushbottom` removes it). `\@textbottom` is inserted by the output routine
  (`\@makecol`) when the column is repacked to `\@colht`, so the fil absorbs the
  shortfall at glue-setting time and suppresses underfull complaints; page-*break*
  decisions still see only what was contributed. Class/package code that instead
  contributes fil-order glue to the main vertical list (e.g. `\vfil` before
  `\clearpage`, `\newpage`'s `\vfil\penalty-10000`) changes the *decisions* as described
  above.

For an incremental system the moral is: the page-break cost function is sensitive not
just to content heights but to the *stretch order profile* of everything on the page —
one more reason page breaking cannot be evaluated without full page state.

### 5.4 Interparagraph and interline glue

- **`\parskip`** (plain: `0pt plus 1pt`): appended to the vertical list when a paragraph
  starts (§1.1).
- **Interline glue** (TbT ch. 15): when a box joins a vertical list, TeX inserts glue to
  keep baselines `\baselineskip` apart, using `\prevdepth` (the depth of the previous
  box):

  ```
  if prevdepth <= -1000pt:  no glue (list start, or after a rule)
  else:
      gap = baselineskip.natural - prevdepth - height(current box)
      if gap >= lineskiplimit:  insert glue gap (with baselineskip's stretch/shrink)
      else:                     insert lineskip glue
  prevdepth := depth(current box)
  ```

  Plain defaults `\baselineskip=12pt`, `\lineskip=1pt`, `\lineskiplimit=0pt`: boxes that
  would touch get 1pt of air, at the price of a locally larger baseline distance.
  `\nointerlineskip` = `\prevdepth=-1000pt` (one-shot); `\offinterlineskip` =
  `\lineskiplimit=\maxdimen` (always take `\lineskip`, set to 0pt).
  The `\baselineskip`/`\lineskip`/`\lineskiplimit` used for a paragraph's lines are those
  in force **when the paragraph is broken** — leading cannot change mid-paragraph.
  Interline glue is computed from box dimensions only — for cached line boxes it can be
  recomputed in O(1) per line when re-stacking pages.

## 6. Kerns

### 6.1 Implicit vs explicit

A **kern** is rigid space: like glue with no stretch or shrink, and (unlike glue) not a
breakpoint by itself.

- **Implicit (font) kerns** are inserted from the font metric's kerning pairs during list
  building (TeX82) or the `kerning` stage (LuaTeX, §2.1) — e.g. pulling 'o' under 'V'.
  They are invisible to the user, skipped by the hyphenation word scanner, and disappear
  and reappear as words are hyphenated. In trace output `\kern2.0pt` (no space) is
  implicit, `\kern 2.0pt` (space) explicit.
- **Explicit `\kern`** works in both horizontal and vertical mode (vertical kerns are
  rigid interline space). Accents are positioned with explicit kerns, which is why an
  `\accent` ends a hyphenatable word.

### 6.2 Kern vs glue at breakpoints

Lines and pages may break **at glue** (if preceded by a non-discardable item), **at a
kern only if it is immediately followed by glue**, and at penalties/discretionaries —
nothing else (§1.2, §3.3). Hence `\hbox{a}\kern0pt\hbox{b}` is unbreakable where
`\hbox{a}\hskip0pt\hbox{b}` is breakable; both the kern and the following glue vanish in
a break. Math-on/off nodes (`\mathsurround`) behave as kern-like items, breakable when
followed by glue.

### 6.3 Math kerns

Inside formulas, spacing is mostly *muglue* (math units, scale with style) inserted
between atom classes, plus explicit `\mkern`/`\mskip`; italic corrections and
script-positioning adjustments materialize as kerns in the `mlist_to_hlist` output. By
the time the paragraph builder sees a formula, all of it is ordinary boxed horizontal
material — breakable only at the math-off boundary and at penalties
(`\binoppenalty`, `\relpenalty`) TeX inserted after binaries/relations.

### 6.4 Margin kerns and font expansion: microtype, "optical vs exact measure"

LuaTeX absorbed pdfTeX's *hz* machinery as core primitives (`\protrudechars`,
`\adjustspacing`, per-character-per-font `\lpcode`/`\rpcode`/`\efcode`,
`\leftmarginkern`/`\rightmarginkern`, `\expandglyphsinfont`); the microtype package is a
front end that sets these.

- **Character protrusion** (`\protrudechars=2`): when a line is packaged, the first/last
  glyph may protrude into the margin by `lpcode/1000 em` / `rpcode/1000 em` (hyphens,
  periods, commas typically protrude right almost fully). The engine implements this with
  **margin kerns** — dedicated kern nodes (`margin_kern`, subtypes left/right) at the
  line edges. The result is an *optical margin*: the ink appears flush while the measure
  is exact — the line hbox is still exactly `\hsize` wide, the protrusion being
  bookkept by the margin kerns inside it. Protrusion is evaluated during line breaking
  (it changes what fits on a line), with a skippable-node scan to find the edge glyphs
  (`\protrusionboundary` can adjust it).
- **Font expansion** (`\adjustspacing`): glyphs may be scaled horizontally within
  per-font limits (`\expandglyphsinfont ⟨font⟩ ⟨stretch⟩ ⟨shrink⟩ ⟨step⟩`, weighted per
  character by `\efcode`), giving the line breaker extra effective stretch/shrink and
  visibly evening out interword spacing. `\adjustspacing=2` applies hz to glyphs and
  kerns during breaking; `3` glyphs only; `1` applies expansion only *after* breaking
  (line breaks then identical to standard TeX, pdfTeX-compatible mode). The chosen
  `expansion_factor` is stored per glyph node.

Two properties matter for the realtime argument. **Determinism**: protrusion and
expansion are pure functions of the paragraph's node list, the font's code tables, and
two integer parameters — no randomness, no context; the same paragraph yields
bit-identical node dimensions every time, which is what lets texlode promise output
identical to a batch LuaLaTeX run with full microtype. **Locality**: both mechanisms live
entirely inside the paragraph builder (they are `tex.linebreak` parameters,
`pdfprotrudechars`/`pdfadjustspacing`); they alter node dimensions within lines but add
no cross-paragraph coupling whatsoever.

## 7. Insertions

### 7.1 The engine model

`\insert n {⟨vertical material⟩}` (n ≠ 255) attaches floating vertical material to the
point of the main text where it is declared. Inserts appearing in horizontal mode
*migrate* to the enclosing vertical list with the line that contains them. Each class `n`
owns four registers (TbT §29.3):

| Register | Role |
|---|---|
| `\box n` | at `\output` time: the class-n material assigned to this page |
| `\dimen n` | maximum total size of class-n material per page (beyond it: split) |
| `\skip n` | glue added once, when the first class-n insert lands on a page (e.g. the footnote rule's space) |
| `\count n` | effective-height factor ×1000 (1000 = full height; 500 = half, for double-column footnotes; 0 = marginalia) |

### 7.2 How the page builder places inserts

When an insertion item reaches the current page (TbT §29.4):

1. First insert of class n on this page: `\pagegoal -= natural(\skip n)` (its
   stretch/shrink go into `\pagestretch`/`\pageshrink`); if `\box n` was non-empty its
   size × `\count n / 1000` is also subtracted.
2. If a class-n insert on this page has already been **split**, add `\floatingpenalty`
   to `\insertpenalties` (this insert cannot be on this page).
3. Otherwise, if the insert fits — box-size cap `\dimen n` respected and
   `\pagetotal + \pagedepth - \pageshrink + effective size <= \pagegoal` — then
   `\pagegoal -= effective size` (height+depth × `\count n / 1000`).
4. If it does not fit, TeX computes the largest splittable portion (same `\vsplit`
   least-cost breakpoint search, using `\splittopskip`/`\splitmaxdepth`), charges the
   split's break penalty to `\insertpenalties`, and reduces `\pagegoal` by the split-off
   part.

`\insertpenalties > 10000` makes the page cost infinite (§3.3) — the mechanism by which
"a footnote was split here" forces an earlier page break. Inside `\output`,
`\insertpenalties` instead reports the *number of held-over insertions*;
`\holdinginserts=1` keeps material out of the boxes so an output routine can inspect and
re-contribute without losing inserts. The output routine is responsible for actually
placing `\box n` (plain: `\ifvoid\topins\else\unvbox\topins\fi \pagebody
\ifvoid\footins\else\unvbox\footins\fi` — unboxing so page glue sets uniformly).

### 7.3 Footnotes and floats

**Footnotes** are the canonical insert (plain: class `\footins`, `\count=1000`,
`\dimen=8in`, `\skip=\bigskipamount`, `\floatingpenalty=20000` so no new footnote starts
on a page where one was split). The text line carrying the footnote mark and the footnote
body are tied to the *same page* by construction — the insert mechanism exists precisely
to solve that pairing for the simple case.

**Floats**: plain TeX implements `\topinsert`/`\pageinsert`/`\midinsert` as insertion
class `\topins` with `\floatingpenalty=0`, so unplaced top inserts carry over page after
page until space is found. **LaTeX's figures/tables are not engine insertions**: LaTeX
manages them with box registers and its own output-routine queues (`\@currlist`,
`\@deferlist`, `\@toplist`, `\@botlist`...), using inserts only for footnotes — but the
structure of the problem is the same: material contributed at point X may be emitted on
any later page, subject to per-page space accounting.

### 7.4 The pairing problem — a genuinely global constraint

Consider the requirement: *"see Figure 3" must land on the same page (or spread) as
Figure 3 itself.* The engine gives no way to express it:

- The callout is a word inside a paragraph; its page assignment is a *consequence* of the
  page builder's greedy break (§3.5), known only when `\box255` ships.
- The float's page assignment is a consequence of the insertion/float queue state — which
  depends on all *earlier* floats (queues are FIFO per class) and on every earlier page's
  spare room.
- Moving the float changes the page's `\pagegoal` accounting, which can move the page
  break, which can move the *callout* to another page — a fixed-point problem spanning
  page pairs, and, transitively, the whole document. Editing one paragraph can dislodge
  a float three chapters later.

This is why float placement (and anything of the same shape: marginalia alignment,
facing-page synchronization, "keep with next") is the paradigmatic **O(document)**
computation, solved in practice by iteration (LaTeX's multiple runs, `\holdinginserts`
juggling, packages re-running output) — and why a realtime system is right to treat it as
background reconvergence rather than keystroke-path work.

## 8. The locality theorem in practice

"Locality theorem" (informal): *given a paragraph's horizontal list and the parameter
snapshot of §1.9, its decomposition into lines — including hyphenation, ligatures, kerns,
glue setting, protrusion, and expansion — is fully determined; no other document content
participates.* Conversely, every vertical-placement decision is a function of unbounded
document prefix state. In table form:

| Computation | Scope | Determined by | Engine site |
|---|---|---|---|
| Hyphenation (discretionary insertion) | **O(word)** | word's glyphs, language, patterns, `\lefthyphenmin`/`\righthyphenmin` | `hyphenate` stage / second pass |
| Ligaturing + implicit kerning | **O(paragraph)** | glyph sequence + font tables | `ligaturing`, `kerning` stages |
| Math typesetting | **O(formula)** | math list + fonts + style | `mlist_to_hlist` |
| Line breaking (Knuth–Plass) | **O(paragraph)** | node list + §1.9 parameter set | `linebreak_filter` / internal |
| Glue setting within each line | **O(line)** | line contents + measure | `hpack` |
| Microtype protrusion / expansion | **O(paragraph)** | node list + font codes + 2 params | inside line breaking / hpack |
| Interline glue (`\baselineskip` mechanics) | O(1) per line pair | adjacent box depth/height + 3 params (`\prevdepth` coupling) | vlist append |
| `\parskip`, interparagraph penalties | O(1) | parameters at paragraph boundary | vlist append |
| **Page breaking** | **O(document prefix)** | all contributions since last break: `\pagetotal`/`\pagestretch`(+orders)/`\pageshrink`, `\pagegoal` erosion, penalties, `\insertpenalties` | page builder |
| Insertions (footnotes) | **O(document prefix)** | per-class box/dimen/skip/count state + held-over splits | page builder + `\output` |
| Float placement / callout–float pairing | **O(document)** | float queues + every page's spare room; fixed-point across pages | output routine (LaTeX) |
| Marks (`\mark`/`\firstmark`/`\botmark`), running heads | O(document) | page-break positions | page builder + `\output` |
| `\write` streams (.aux/.toc), cross-references | O(document), multi-pass | shipout order + previous runs | shipout + macro layer |
| Vertical (page) position of any given line | O(document prefix) | all preceding page breaks | page builder |

Practical corollary for texlode's architecture: the entire left column above — everything
that changes the *pixels of a paragraph* — is recomputable from the edited paragraph
alone in O(paragraph) time (~1 ms), while the right column — everything that changes
*which page pixels land on* — is exactly the set of computations word processors have
always deferred to a background pass. The engine's own structure, not any approximation,
draws that line: TeX optimizes globally within paragraphs and greedily across pages, and
LuaTeX exposes the seam as replaceable Lua stages with `tex.linebreak` as the pure-function
witness.
